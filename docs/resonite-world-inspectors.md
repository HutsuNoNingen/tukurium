# インスペクタを複数の共有ワールドパネルにする

調査日：2026-10-23。Resoniteのインスペクタは、ワールド内のSlotにUI、表示対象への参照、掴む機能を付けて構成している。Kokoverseでも、パネルを独立した共有オブジェクトにすると「箱用と画像用のインスペクタを並べ、同じ画面を一緒に操作する」体験を作れる。

本書は調査結果と実装案を記録する。同日、この調査に基づく共有ワールドパネルを実装した。以下の調査・提案は設計時の記録で、実装済みの範囲は末尾に記す。

追記：その後、共有パネル内のLuaドラフトと複数カーソルの共同編集を実装した。本書のローカルドラフトに関する記述は初版時点のもの。現在の構成とResoniteとの操作上の差は、[インスペクタUX差分](resonite-inspector-ux-gap.md)を参照。

## Resoniteではパネル自体がワールドのオブジェクトになっている

インストール済みの `FrooxEngine.dll` を静的に解析した。以下の型名とメソッド名は、そのバージョンで確認した根拠を示す。

| 確認した動作 | 根拠 |
|---|---|
| 開くたびに別のパネルを生成する | `DevTool.CreateInspector` が毎回Slotと `SceneInspector` を生成。`InspectorTool` も `World.AddSlot` で生成する |
| パネルごとに階層の起点と選択対象を持つ | `SceneInspector.Root` は `RelayRef<Slot>`、`ComponentView` は `SyncRef<Slot>`。`RelayRef` も `SyncRef` を継承する |
| 掴んで移動・回転・拡縮できる | `RadiantUI_Panel.SetupPanel` が `Canvas` と `Grabbable` を付け、`Scalable` を有効にする。Slotの位置・回転・スケールも同期フィールド |
| ピン留めするとユーザーに追従する | `ButtonParentUnderUser` がパネルをユーザーのルートSlotの子にする。解除時は記録した親へ戻す |
| 閉じるとパネルを削除する | 共通パネルの閉じるボタンは、そのパネルのルートSlotを破棄対象にする |
| 対象に応じて部品・編集欄を生成する | `WorkerInspector.BuildInspectorUI` が同期メンバーを列挙し、`SyncMemberEditorBuilder` が型に合うエディターを作る |

同じ箱を指すパネルを複数作ることも、別々の物体を指すパネルを並べることもできる構成になっている。階層の起点と右側の選択対象は別なので、階層を上へ移動しても選択を維持できる。[公式Wikiにも、新しいパネルの開き方とこの選択挙動が記載されている](https://wiki.resonite.com/Scene_Inspector/en)。

`LocalUserSpace` という名前は「自分だけに見える領域」を意味しない。実装はユーザーのルートSlotの親を返し、ここでのパネル生成は `AddSlot` を使っている。ローカル専用の `AddLocalSlot` とは別経路。セッション内で共有することと、ワールド保存に含めることも別で、保存対象かどうかは親を含む永続化設定に依存する。

`SceneInspector.OnChanges` は権威を持つ側で階層と部品のUIを作り直す。Resoniteではパネルの配置に加え、その内側のUIも同期するワールド要素として組み立てている。一方、描画用の内部データにはローカルSlotも使う。

## スクロールや編集中の文字も共有し、キー入力は本人だけが処理する

「表示対象だけ共有して、残りのUI状態は全部ローカル」という構造ではなかった。

| 状態 | 静的解析で確認した扱い |
|---|---|
| 階層の起点・選択対象 | パネルごとの同期参照 |
| パネルの位置・回転・スケール、Canvasのサイズ | 同期フィールド |
| スクロール位置 | `UIX.ScrollRect.NormalizedPosition` が `Sync<float2>` |
| 入力欄の文字、キャレット位置、選択範囲 | `UIX.Text.Content`、`CaretPosition`、`SelectionStart` が同期フィールド |
| 誰がどの入力欄を編集中か | ユーザーごとの `FocusManager._currentFocus` が同期参照。全ユーザーから編集中の人を調べる |
| キーボードから文字を読む処理 | `TextEditor.Focus` がローカルユーザーの場合だけ編集処理を開始 |
| レーザーの当たり位置・ホバー・ドラッグ継続中の情報 | `Canvas` 内の入力元別の一時データ。同期フィールドとは分けて保持 |

`TextField` は、すでに誰かが編集中なら新たにフォーカスを取らない。ただし、このチェックだけで厳密な同時編集ロックが保証されるとは判断しない。遅延がある状態での同時クリックは、実機での追加検証が必要。

文字入力中は `FocusManager.BeforeInputUpdate` がキーボード入力をブロックする。Kokoverseでも、ワールド内の入力欄へ文字を打っている間は移動・ジャンプに入力を渡さず、チェックボックスにフォーカスがあるだけならSpaceでジャンプできる区別を維持する必要がある。

数値などの反映は `PrimitiveMemberEditor` の設定による。通常はパースできた値を入力中に反映し、終了時にも反映する。`NoContinuousParsing` の指定やURI型などには終了時の反映を使う。入力開始時には表示値の自動更新を外すので、編集中の文字が外部更新で直ちに置き換わるのを避けられる。チェックボックスは `BooleanMemberEditor` から対象フィールドへ直接書き込む。

## レーザーの交点をパネル内の座標へ変換している

`Canvas.ProcessTouchEvent` はワールド座標の交点をパネルのローカル座標に変換し、単位倍率を適用してUI要素を探す。入力元ごとにホバー先やドラッグの保持先を記録するため、押したままポインターが動く操作も扱える。

Canvasにはレーザー・物理タッチの受け付け、裏側からの操作拒否、レーザーを通すかどうかの設定がある。[Canvasの公式説明](https://wiki.resonite.com/Component%3ACanvas)でも確認できる。ただし、このバージョンの標準 `InspectorPanel` は `AcceptPhysicalTouch` を無効にしており、Canvas全体の能力と標準インスペクタの設定は異なる。

## Kokoverseでは共有データをRustに、画面生成と入力をGodotに置く

以下は今回の調査に基づく実装案であり、Resonite内部の再現仕様ではない。現在のホストによる編集検証とrevisionを引き続き使う。

パネルには安定したIDを付け、箱や画像と同じように生成・移動・回転・拡縮・削除できるようにする。パネルAの選択を変えても、パネルBの対象は変えない。2Dインスペクタも同じ表示部品を使い、開く場所だけを変える。

配置・サイズ・入力面を担う `WorldPanel` と、対象参照を持つ `InspectorView` は別の部品にする案を推す。将来、アセット一覧やUGCで作る画面にも同じパネル機能を使え、インスペクタ固有の選択処理を持ち込まずに済む。

| データ | 持たせる場所・共有範囲 |
|---|---|
| パネルID、表示の種類、対象アドレス、階層の起点 | Rustのパネル部品。参加者へ同期 |
| Transform、物理サイズ、固定位置または追従するユーザー | Rust。参加者へ同期 |
| スクロール位置・展開中の項目 | パネルごとに共有。同じパネルを見る人には同じ箇所を表示 |
| 編集中のユーザー、対象フィールド、文字列、キャレット・選択範囲 | 期限付きの編集セッションとして共有。ワールドには保存しない |
| キー入力先、マウスの捕捉先、IME変換途中の文字、描画テクスチャ | 操作中のGodotだけで保持 |
| 対象の確定値・編集revision | 既存のRust側データ。パネルが複数あっても正本は一つ |

同じパネルを一緒に見る場合、共有スクロールと編集者表示があるほうが「ここを変更している」が伝わる。別の場所を読みたい人はパネルをもう一つ開く。長いScriptの未確定コードは、現在のように自分のドラフトとして保持し、公開操作で反映する。

同時編集の占有はパネルIDだけで管理せず、対象アドレスとフィールドIDで管理する。同じ箱を別々のパネルから開いても、同じ数値を同時に上書きしないため。ホストが期限付きの占有を承認し、切断・タイムアウトで解除する。値の確定時には既存のrevision検証も行う。

Godotは `Control` を `SubViewport` に描き、テクスチャを3Dの板に貼る。ポインターの交点からパネル座標を求め、該当するViewportへ入力を渡す。[SubViewportは3D空間へのUI表示に利用できるが、単独では入力イベントが自動転送されない](https://docs.godotengine.org/en/stable/classes/class_subviewport.html)。他ユーザーの操作は共有状態として描画し、その人のキーイベントを自分の入力系へ注入しない。

パネルのColliderは把持・ポインター操作に使い、既定ではプレイヤーを押し返さない設定にする。操作面の左クリックはUIへ、右クリックは既存の把持処理へ渡し、同じ入力で背後の箱まで操作しない。入力欄のドラッグはパネル外へ出ても解放まで保持する。

## 実装は複数パネルの共有から始める

最初の完了条件は、箱と画像のインスペクタを別々に出し、2人が同じパネルを操作して変更を確認できること。完全なSlot階層がなくても、現在のオブジェクト一覧とフィールド定義から着手できる。

| タスク | 実装内容 | 確認する結果 |
|---|---|---|
| 1. インスペクタ表示を独立させる | 現在の単一の選択・フォーム状態を、パネル単位の表示部品と編集状態へ分割 | 2Dで2つ開いても対象・未確定入力・応答先が混ざらない |
| 2. パネルの共有データを追加する | パネル部品、生成・削除・対象変更、Transform、サイズ、上限 | 2クライアントと途中参加で同じパネル群を復元できる |
| 3. ワールド内で表示・操作する | SubViewport、交点からの入力転送、掴む・回す・拡縮、入力捕捉 | 箱用と画像用を並べて操作でき、裏面・背後への誤操作がない |
| 4. 共同編集の表示を追加する | スクロール・展開状態、編集者・入力表示、フィールド占有、失効処理 | 同じパネルで編集を共有でき、別パネルからの競合や切断で入力が壊れない |
| 5. 追従・保存・負荷対策を追加する | ピン留め、保存する設定と一時状態の分離、画面更新の制限 | 再起動で配置を復元し、多数のパネルで操作性を確認できる |

対象の削除時は「対象が削除されました」と表示して参照を解除する案を推す。パネルも直ちに消すより、何が起きたか分かりやすい。これは、階層の起点が削除されるとパネルを破棄するResoniteの実装とは異なる。

初版の上限は16枚を候補とし、計測で調整する。これは性能測定済みの値ではない。見えていないパネルの描画を止め、同じ対象の購読をまとめ、物理サイズと描画解像度を別に制限する。ピン留めするユーザーが退出した場合は最後の位置に残し、編集中の状態は解除する案とする。

## Kokoverseに実装した範囲

`WorldPanel` と `InspectorView` を別のRust ECS Componentにし、生成・複製・削除、対象変更、通常のTransform、ピン留め、スクロールを同期・保存する。パネルは最大16枚、既存の128物体上限にも数える。初期表示は720×960、物理サイズ1.2×1.6m。FPSの把持処理で移動・回転・拡縮でき、Colliderは既定で非solid。ピン留めはホストが参加者の姿勢から更新し、追従先がいなくなったら最後の位置に残す。

Godotにはパネル単位でSubViewportと独立した編集UIを作る。2Dインスペクタは従来のUIを保持している。Slotの親子構造はまだないため、ワールド内パネルの対象はフラットなオブジェクト選択欄で選ぶ。位置・回転・スケール・色・Collider・名前を編集し、動画の基本再生操作とScriptエディターへの導線も持つ。

共有パネルが指す対象には、操作を受け取らない表示用ギズモを各クライアントで生成する。操作中のプレビューに追従し、本人の選択・操作ハンドルとは分ける。ギズモのメッシュやポインター位置をワールドへ保存する方式にはしない。

入力欄は `edit_session` でホストからフィールド単位の編集占有を取得する。ドラフト・キャレット・選択範囲・編集中の人は `edit_sessions` で配信する。同じユーザーが別パネルから同じ欄を開く場合も占有を区別する。キー入力は本人のGodotだけが処理し、受信側は表示するだけ。6秒間更新がなければ占有を失効させ、対象・パネルの削除でも解放する。通常の編集要求にも占有を確認し、最終的には既存のrevision検証を通す。長いScriptソースのドラフトは引き続きローカル。

実装箇所は `crates/core/src/panels.rs`、`edit_sessions.rs`、`crates/engine/src/edit_sessions.rs`、`client-godot/world_panel.gd`、`world_panels.gd`、`inspector_view.gd`。`tests/panels-integration.mjs --rendered` で、2つのGodotの共有入力表示、3D交点からの入力、独立した対象、スクロール、ギズモ追従、把持・回転・拡縮、ピン追従、途中参加、保存・復元、対象削除を検証する。多数パネルでの性能と日本語IMEの実機操作は未測定。
