# ローカルのセッションとアイテム保存を使う

ユーザー名入力、セッション作成・一覧からの参加、個人ライブラリへの保存・再配置・共有を、ローカルの管理サーバーにつないで試せる。ワールドの同期にはKokoSyncを使い、管理サーバーがユーザー、保存版、利用権を保持する。

## 起動と停止

リポジトリのルートから実行する。開発用のセットアップ済み環境が必要で、実行ファイルがなければRustをビルドする。変更後の再ビルドには `-Build` を付ける。

```powershell
./scripts/start-local.ps1 -Build
```

画面の「HN」に名前を入力して「Start」を押す。同じHNを入力すれば、別のプロファイルやPCでも同じ利用者になる。「作成」で自分がホストのセッションを作るか、一覧の「参加」で入る。

起動すると、Engineのログ用コンソールとGodotのアプリ画面が開く。ログインやワークショップのGUIはGodot画面内に表示する。Engineのコンソールを×で閉じると、ホストのワールドを保存し、AdapterとGodotも終了する。ログはプロファイルの `engine-error.log` にも残る。

起動中にStartを再実行すると、Godotを前面に戻す。Godotだけ閉じた場合は、動作中のEngineへ再接続して画面を開き直すため、事前にStopを実行する必要はない。

同じPCに別の利用者を用意する場合は、別プロファイルで起動し、異なるHNを入力する。

```powershell
./scripts/start-local.ps1 -Profile guest
```

「退出」は保存してホームへ戻る操作。アプリ全体を停止するときはEngineのコンソールを閉じるか、次を実行する。スクリプトはホストのワールドを保存してから退出し、Adapterも停止する。保存失敗時には停止せず、エラーを返す。

```powershell
./scripts/stop-local.ps1
./scripts/stop-local.ps1 -Profile guest
```

ほかのプロファイルをすべて停止したあと、共有サーバーも止める場合は `-Services` を付ける。アプリのウィンドウを閉じるだけではEngineは終了しない。

配布ZIPでは `StartLocal.bat` / `StopLocal.bat` がこの経路を使う。`Start.bat` / `Stop.bat` は [公開サーバー版](deployment.md) を起動する。従来の固定ルーム版は `StartLegacy.bat` / `StopLegacy.bat` に残している。

## サーバー構成と保存先

| 対象 | 接続先・保存先 |
|---|---|
| 管理サーバー | `http://127.0.0.1:8787` |
| KokoSyncローカル中継 | QUIC `127.0.0.1:48001` / HTTP `127.0.0.1:48000` |
| 管理DBと素材 | `.run/local/server/catalog.sqlite` と `assets/` |
| ホストのワールド | `.run/local/<profile>/worlds/<session-id>.json` |
| ローカル素材キャッシュ | `.run/local/<profile>/assets/` |
| 本人情報 | `%LOCALAPPDATA%/Kokoverse/profiles/<profile>/profile.dat` |
| 起動ログ | `.run/local/` と `.run/local/<profile>/` |

内部のセッションキーはWindowsのDPAPIで保護する。同じHNならプロファイルが違っても同じユーザーである。前後の空白は除き、大文字小文字は区別する。共有相手は画面に表示されるユーザーコードで指定する。

サーバー単体は `kokoverse-asset-server --listen 127.0.0.1:8787 --data-dir <directory> --relay 127.0.0.1:48001` で起動できる。初期の保管量上限は利用者あたり1 GiBで、`--quota-bytes` で変更する。サーバーは初版ではループバックにのみ待ち受ける。

## 保存と共有

ワールドでアイテムを選択し、「ホーム / ライブラリ」を開く。「マイライブラリ」の「選択中のアイテムを保存」で、見た目・設定・スクリプトを含む保存版を登録する。「ワールドに配置」で新しい個体として配置し、各個体のスクリプト状態は分離する。

詳細欄には作者や保存時刻を表示する。「ユーザーに直接渡す」では相手のユーザーコードを指定する。現在はライセンスの選択欄や、保存・改変・再配布の制限を設けていない。

配置物の作者・所有者・元の保存版・編集ユーザーと時刻は、ワールド保存にも含める。別のHNの配置物も保存・編集できる。保存した人へ原作者を書き換えず、派生元の記録を引き継ぐ。

モデル・動画はファイルとして保管する。画像パネルの画像は既存の形式を保ち、初版では保存版に埋め込む。ライブラリのサムネイルは、画面を開く直前の縮小画像である。

## HNの切り替えとワールドの再開

本人情報ファイルの移行は不要。同じサーバーで同じHNを入力すれば、同じライブラリを開ける。HNの変更は別ユーザーへの切り替えになり、以前のHNに戻れば以前のライブラリを開ける。すでに同じHNで複数の利用者がいた場合は、保存版・素材へのアクセスをまとめる。

終了したワールドを再び開く場合は、「保存ワールドから…」でホストの保存JSONを選び、セッションを新しく作る。元のファイルを読み込み、新しいセッションIDの保存先へ保存する。素材は同じプロファイルのキャッシュを使うため、ワールドファイルだけを別の環境へ移しても素材一式の移行にはならない。

## APIと検証

実装のHTTP契約は [local-service.openapi.json](local-service.openapi.json)。認証用の `POST /v1/users`、素材用の `PUT/GET /v1/assets/{hash}`、管理操作用の `POST /v1/rpc` を使う。設計時のREST形式の候補を、初版では少数のHTTP入口にまとめている。

管理DBはSQLiteのトランザクションで保存する。素材は一時ファイルへ転送し、SHA-256・形式・サイズを検証してから登録する。転送は同時に2件、1素材128 MiBまで。保存と共有の同じリクエストIDの再送では、重複した保存版や利用権を作らない。

```powershell
. ./scripts/env.ps1
cargo test --workspace --locked
cargo clippy --workspace --all-targets -- -D warnings
node tests/managed-integration.mjs
node tests/managed-integration.mjs --rendered
```

統合テストは独立したデータディレクトリとポートを使う。本人情報、セッション、権限、素材の取得、再試行、サーバー再起動、Godot画面の操作を確認する。同じPC上の複数プロセスによる検証であり、別PC・インターネット経由の検証とは区別する。

## 現段階の範囲

現在は単一オブジェクトのアイテム保存、公開セッション、[ワークショップの公開・取得](workshop.md)に対応する。無料ストア、複数部品のアイテム化、外部への動的参照、決済、ホストの自動交代は未実装である。

管理APIはサインイン、本人の一覧の編集、セッション管理、形式・容量を検証する。サインイン済みなら既知の保存版IDや素材ハッシュから取得でき、利用条件の値では拒否しない。正式なライセンス機構は[作品の境界](item-boundaries-and-rights.md)を整えてから検討する。

バックアップは共有サーバーを停止してから、管理DB・素材・必要なワールド保存をまとめてコピーする。SQLiteの補助ファイルが残っている場合も同じディレクトリを一式保管する。
